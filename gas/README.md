# カエル見つけたマップ — GAS デプロイ手順

投稿の受け口（`gas/Code.gs`）を、Google スプレッドシートに紐づく Apps Script（コンテナバインドスクリプト）としてデプロイする手順です。研究室の担当者が実施することを想定し、番号順に進めれば完了するように書いています。

設計の正は `docs/DESIGN.md`（特に §3.1〜§3.3）です。列の仕様や検証ロジックを変えたいときはそちらを先に確認してください。

---

## 1. スプレッドシートの準備

1. Google ドライブで新しいスプレッドシートを作成する（「新規 → Google スプレッドシート」）。
2. わかりやすい名前を付ける（例：「カエル見つけたマップ 投稿データ」）。
3. メニューから **拡張機能 → Apps Script** を開く。エディタが新しいタブで開く。
4. デフォルトで `Code.gs` というファイルが1つある状態になっている。中身を全て削除し、このリポジトリの `gas/Code.gs` の内容を丸ごと貼り付ける。
5. 上部のプロジェクト名（「無題のプロジェクト」）をクリックし、わかりやすい名前に変更する（任意）。
6. `Ctrl+S`（またはフロッピーアイコン）で保存する。

## 2. 初期セットアップ（`setup` の実行）

1. Apps Script エディタ上部の関数選択プルダウンから **`setup`** を選ぶ。
2. 「実行」ボタン（▷）をクリックする。
3. 初回は権限承認の画面が出る。
   - 「権限を確認」→ 自分の Google アカウントを選択 → 「詳細」→「（プロジェクト名）に移動（安全ではないページ）」→「許可」の順にクリックする。
   - これは Google の一般的な警告表示で、自分が書いたスクリプトを自分のアカウントで実行するために必要な手順です。
4. 実行が終わると、スプレッドシートに **`records`** という名前のシートが作成され、1行目に列名（`submitted_at`, `record_id`, `lat`, `lng` …）が太字・固定表示で入っている。
5. すでに `records` シートがある場合は、1行目の列名だけが上書きされる（データ行は消えない）。

## 3. ウェブアプリとしてデプロイ

1. Apps Script エディタ右上の **「デプロイ」→「新しいデプロイ」** をクリック。
2. 左の歯車アイコンから種類を選ぶ画面で **「ウェブアプリ」** を選択。
3. 設定：
   - 説明：任意（例：「初回公開」）
   - 実行するユーザー：**自分**
   - アクセスできるユーザー：**全員**
4. 「デプロイ」をクリックし、権限承認が出たら 2. と同様に許可する。
5. 発行された **ウェブアプリのURL**（`https://script.google.com/macros/s/xxxxxxxx/exec` の形式）をコピーする。
6. このリポジトリの `config/map.json` の `"gasUrl"` にこのURLを貼り付ける。
7. フロントエンドを再ビルド（`npm run build`）し、ホスティング先（GitHub Pages 等）へ再デプロイする。

## 4. 動作確認

**疎通確認（ping）**

ブラウザで以下を開く（`<URL>` は3.で発行したURLに置き換える）。

```
<URL>?action=ping
```

`{"ok":true,"version":"1.0.0","accept_until":null}` のような JSON が表示されれば成功。

**投稿確認（curl）**

```bash
curl -L -X POST -H "Content-Type: text/plain" \
  --data '{"lat":43.1961,"lng":141.7759,"species_code":"amagaeru","observed_year":2026,"observed_month":7,"observed_day":15,"count_category":"3","method":"seen","confidence":"high","habitat":"paddy","comment":"","source":"test","app_version":"1.0.0"}' \
  "<URL>"
```

`{"ok":true,"record_id":"..."}` が返り、スプレッドシートの `records` シートに1行追加されていれば成功。

**公開ピン確認**

```
<URL>?action=pins
```

`[{"lat":43.196,"lng":141.776,"species_code":"amagaeru","ym":"2026-07"}]` のような配列が返れば成功（座標は公開用に丸められている）。

## 5. 受付終了日の設定

祭り後も無期限で受け付ける設定が初期状態です。締め切りたい場合のみ設定してください。

1. Apps Script エディタ左メニューの **歯車アイコン（プロジェクトの設定）** を開く。
2. 「スクリプト プロパティ」セクションの「スクリプト プロパティを追加」をクリック。
3. プロパティ名に **`ACCEPT_UNTIL`**、値に **`2026-12-31`** のような日付（`YYYY-MM-DD`形式）を入れて保存する。
4. 設定した日の日本時間 23:59:59 を過ぎると、投稿は `{"ok":false,"error":"closed"}` で拒否されるようになる（既存データは残る）。
5. 無期限に戻す場合は、このプロパティを削除する。

## 6. Code.gs を更新したとき（再デプロイ）

**URL は変わりません。** 一度発行したウェブアプリURLは、以下の手順で更新しても同じものを使い続けられます。フロント側の `gasUrl` を書き換える必要はありません。

1. Apps Script エディタで `Code.gs` の中身を新しい内容に貼り替えて保存する。
2. 「デプロイ」→ **「デプロイを管理」** を開く。
3. 既存のデプロイ（鉛筆アイコン）をクリックして「編集」に入る。
4. 「バージョン」のプルダウンで **「新バージョン」** を選ぶ。
5. 「デプロイ」をクリックする。

## 7. 割り当て（クォータ）について

GAS には同時実行数や1日あたりの実行時間などの割り当て上限があります。以下は **実装時点（2026年9月）の目安**であり、Google 側の仕様変更で変わる可能性があるため、正式な数値は必ず公式ドキュメントで確認してください。

https://developers.google.com/apps-script/guides/services/quotas

祭り規模（数百〜千件/日程度の投稿）であれば、通常は問題にならない見込みです。もし投稿が集中して失敗が増えるようであれば、上記ページの上限値と実際の投稿数を照らし合わせて調査してください。

## 8. CSVダウンロード

研究室が投稿データを取得する方法です。

1. スプレッドシートを開き、**ファイル → ダウンロード → カンマ区切り値（.csv）** を選ぶ。
2. `records` シートがダウンロードされる。

Excel で開いたときに日本語が文字化けする場合は、`scripts/export.py` を使うと BOM 付き UTF-8 の CSV（`records_qgis.csv`）と GeoJSON（`records.geojson`）を作れます。詳しくは `scripts/export.py` 冒頭のコメント、またはリポジトリのトップの案内を参照してください。

```bash
python scripts/export.py <ダウンロードしたCSV> --out-dir output
```

## 9. 障害時の手順（RUNBOOK 抜粋）

詳細は `docs/RUNBOOK.md` を参照してください。ここでは GAS 側の最低限の確認手順のみ記載します。

1. Apps Script エディタ左メニューの **「実行数」** で直近の `doPost` / `doGet` の実行ログとエラーを確認する。
2. `records` シートが意図せず削除・改名されていないか確認する（シート名は `records` 固定）。
3. どうしても復旧しない場合は「6. 再デプロイ」の手順でもう一度デプロイし直す（URLは変わらない）。
4. それでも投稿を受け付けられない場合に備え、紙の投稿用紙をブースに用意しておく（`docs/RUNBOOK.md` 参照）。

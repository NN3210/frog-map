# RUNBOOK — 祭り当日の運用手順

「カエル見つけたマップ」を大学ブースで運用するための手順書です。エンジニアでない担当者でも進められるよう、番号順にまとめています。困ったときの対処は「障害時」の表を見てください。

前提となる設計・仕様は `docs/DESIGN.md`、GASのデプロイ手順は `gas/README.md` を参照してください。

---

## 1. 前日まで（チェックリスト）

準備は祭りの前日までに済ませておきます。上から順にチェックしてください。

- [ ] **GASの疎通確認**：ブラウザで `<GASのURL（config/map.json の gasUrl）>?action=ping` を開き、`{"ok":true,"version":"1.0.0","accept_until":null}` のようなJSONが返ることを確認する。
- [ ] **テスト投稿を1件行う**：本番URLをスマホやPCで開き、地図をタップして実際に1件投稿する。スプレッドシート（`records` シート）に行が1行増えることを確認する。
- [ ] **テスト行を削除する**：確認できたら、スプレッドシート上でそのテスト投稿の行を削除する（本番データに紛れ込まないように）。
- [ ] **QR掲示物をA3以上で印刷する**：`docs/qr/` にある印刷用PDF（`python scripts/make_qr.py` で生成したもの）をテント前・机上に置けるサイズで印刷する。
- [ ] **ブースのタブレットでアプリを開いておく**：通信が弱い来場者向けに、ブース常設のタブレットで本番URLを開いた状態にしておく（電源・Wi-Fi/回線も確認）。
- [ ] **紙の投稿用紙を印刷する**：本章末の「紙の投稿用紙」の表をA4等で印刷し、予備を含め十分な枚数を用意する。

## 2. 当日の流れ

1. **QRコードを掲示する**：テント前・机上にQR掲示物を置く。共用タブレットにも同じアプリを開いておく。
2. **スプレッドシートをブースPCで開いておく**：担当者用PCで投稿先のスプレッドシートを開いたままにし、来場者に「今もこうやって増えていくんですよ」と見せる（投稿が増える様子は客寄せに使える）。
3. **来場者への声かけ例**（そのまま使える文言）：
   - 「スマホでこのQRコードを読むと、カエルを見た場所を教えてもらえる地図が開きます。地図をタップするだけなので、よかったら試してみてください」
   - 「お子さんと一緒に、カエルを見た場所や鳴き声を聞いた場所をタップして教えてもらえますか？名前や連絡先は聞きませんので、気軽にどうぞ」
   - 「電波が弱いときは、こちらのタブレットからでも投稿できますよ」
4. **共用タブレットで投稿してもらう場合の注意**：このアプリは端末情報（Cookie・位置情報API・広告ID等）を一切取得しない設計のため、複数人が同じ端末で入れ替わり投稿しても、追加の対応（ログアウト操作や履歴削除など）は不要です。普段どおり渡して使ってもらって構いません。

## 3. 障害時：症状 → 確認 → 対処

| 症状 | 確認すること | 対処 |
|---|---|---|
| (a) 送信失敗が続く（「電波の良いところでもう一度お試しください」が繰り返し出る） | 1. ブラウザで `<GASのURL>?action=ping` を開き、`{"ok":true,...}` が返るか確認する。<br>2. Apps Script エディタ左メニューの「実行数」で `doPost` のエラーを確認する。<br>3. 短時間に投稿が集中していないか（Googleの割り当て超過の可能性）を確認する。 | `ping` が返らない・エラーが出続ける場合、原因がGoogle側の割り当て超過（一時的な混雑）であれば、その日は無理に直そうとせず、紙の投稿用紙（本章末）に切り替えて後日まとめて入力する。復旧しない場合は翌日まで待つ。 |
| (b) 地図が表示されない（グレーのまま・タイルが読み込まれない） | 1. 他のサイトは開けるか（会場の回線自体の問題でないか）を確認する。<br>2. 地理院タイル（`https://cyberjapandata.gsi.go.jp/`）が他の端末・回線でも表示されないか確認する（地理院側のサービス状態の可能性）。 | 回線側の問題なら、電波の良い場所への移動やブース内Wi-Fiの再起動を試す。地理院タイル側の問題（サービス障害）と分かった場合は復旧を待つしかないため、口頭・紙の投稿用紙での対応に切り替える。 |
| (c) GAS（受け口）を再デプロイしたい | `Code.gs` を書き換えた、または既存のデプロイが壊れた場合。 | 手順は `gas/README.md` の「6. Code.gs を更新したとき（再デプロイ）」を参照。URLは変わらないため、フロント側の設定変更は不要。 |
| (d) どうしても投稿できない | 上記(a)(b)が短時間で直らない場合。 | 紙の投稿用紙（下記）に記入してもらい、後日まとめてスプレッドシートに手入力する。 |

### 紙の投稿用紙（バックアップ用）

デジタルで投稿できないときに使う簡易フォーマットです。投稿フォームと同じ項目を持たせています。後日、担当者がスプレッドシート（`records` シート）に手入力してください（`source` 列には `paper_backup` のように記入し、紙経由と分かるようにする）。

| 項目 | 記入欄 |
|---|---|
| 見た・聞いた場所（住所や目印） | |
| 種（ヒガシニホンアマガエル／トノサマガエル・トウキョウダルマガエル／エゾアカガエル／ヒキガエル／ツチガエル／ウシガエル／わからない） | |
| いつ見た・聞いた（年／年月／年月日、わかる範囲で） | |
| 何匹くらい（1〜10／たくさん／少ない・数えていない／不明） | |
| 確認方法（姿を見た／鳴き声だけ／両方） | |
| 自信（自信あり／たぶん／自信なし） | |
| 環境（田んぼ／用水路・川／池・沼／林・草地／道路・住宅地／その他） | |
| ひとこと（※お名前・住所・電話番号など個人が分かることは書かないでください） | |

## 4. 祭り後

1. **受付終了日を設定する（締め切る場合のみ）**：`gas/README.md` §5 の手順で、Apps Script の「スクリプト プロパティ」に `ACCEPT_UNTIL`（例：`2026-12-31`）を設定する。設定した日のJST 23:59:59を過ぎると新規投稿は `{"ok":false,"error":"closed"}` で拒否されるようになる（既存データは残る。無期限に戻す場合はこのプロパティを削除する）。
2. **CSVをダウンロードする**：スプレッドシートの「ファイル → ダウンロード → カンマ区切り値（.csv）」で `records` シートを保存する。
3. **`export.py` で変換する**：

   ```bash
   python scripts/export.py <ダウンロードしたCSV> --out-dir output
   ```

   `output/records_qgis.csv`（UTF-8 BOM付き、Excelで文字化けしない）と `output/records.geojson`（QGIS等のGIS用）が出力される。不要な行を除きたい場合は `--exclude-status invalid,out_of_area` のように指定できる。

4. **`review_status` 列の見方**：投稿データを扱うときは、この列で信頼度を判断する。

   | 値 | 意味 | 扱い方の目安 |
   |---|---|---|
   | `unreviewed` | 未確認（通常の投稿）。地図への公開表示対象にもなる | そのまま集計・利用してよい |
   | `suspect_duplicate` | 直近の投稿と内容（位置・種・時期・個体数）が完全一致し、2分以内に送られた＝重複の疑い | 同一人物の連打・誤操作の可能性。集計時は重複除外を検討する |
   | `out_of_area` | 座標が対象範囲（北海道を覆う矩形）の外 | 誤タップやテスト投稿の可能性が高い。集計から除外することが多い |
   | `invalid` | 選択肢外の値が送られた、または未来日など不正な内容だった（改竄・不具合の痕跡として残す） | 通常は集計に使わない。件数が多い場合は原因調査（不正操作・フロントの不具合など）を行う |
